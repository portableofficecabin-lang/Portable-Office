requests listed in section 7, and nothing is merged or deployed without the owner's confirmation.

**Baseline:** `main` at `976b76c` (13 Oct 2026), production build served locally and crawled from its own
`/sitemap.xml` — **230 URLs**. The full page-by-page matrix is in

## 2. Scope and method

- **Discovery:** URLs come from the site's own `/sitemap.xml` (230 unique paths). Page types are assigned
  from the code's own data: `products.ts` (product URLs), `cityPages.ts`, `seoPromotions.ts`, route folders.

  | Type | Count | | Type | Count |
  |---|---|---|---|---|
  | product | 45 | | city | 27 |
  | category | 17 | | directory | 1 |
  | hub (`/products`, portable-cabin hub, toilet hub, metal hub, marketplace, promotions) | 6 | | promotion | 100 |
  | guide (`/products/<parent>/<child>`) | 13 | | blog | 6 |
  | policy | 7 | | other static + home | 8 |

- **Fetch:** no redirects followed, Googlebot user agent, HTML exactly as a crawler that runs no JavaScript
  receives it. Content is measured inside `<main>` (header/footer/floating buttons excluded) and outside
  React's hidden streaming buffer.
- **Statuses:** each dimension rolls up named checks — *Already implemented* (all pass), *Needs improvement*
  (some fail), *Missing* (all fail), *Requires verification* (only the business-evidence check fails —
  cannot be fixed by writing copy), *Not applicable*. Thresholds are constants at the top of
  `scripts/seo/site-inventory.ts` (title 20–65, description 70–160, ≥2 H2, ≥3 visible FAQs, similarity flag
  50 %, FAQ "templated" when on ≥4 pages).
- **Validation of the tool:** every failing check class was spot-checked against the raw HTML before being
  reported. Four false-positive classes were found and fixed in the tool (numbered FAQ badges, `"336300.00"`
  vs `336300`, JSON-LD name being the feed title by design, guide CTA bands worded "View … Range").

## 3. Findings by dimension

### 3.1 Technical SEO

- **Strong:** status, canonical, robots, single server H1, unique titles/descriptions, image `alt` on every
  `<img>`, sitemap = indexable set (no noindex URL in the sitemap), `?page=` pagination disallowed (by
  design — static rendering is kept; see the robots file comment).
- **F1 — category duplication.** Outline of `/products/category/security-cabins`: H1, category grid (2
  products), then *Full Catalogue — All Products A–Z* (all 45 products with prices) and *Find the Right
  Portable Structure* (all 17 categories + 20 fixed links). ~1,700 words, of which the category's own
  content is a small fraction. The A–Z block was deliberately kept as a crawl aid (comment in
  `src/views/Products.tsx`), so changing it is an owner decision — proposal A1 in section 8.
- **Titles over 65 characters:** 44 product titles are the Merchant feed titles (`feedTitle`), shared with
  the feed and JSON-LD — protected; 9 category titles are held as C7 pending GSC data; 9 others are minor.
  Google truncates rather than penalises long titles; no change proposed without data.
- **Meta descriptions outside 70–160:** 11 categories (short — #86 writes real ones), 6 city pages
  (owner-written, 162–196 chars), `/cities-we-serve` (204 → fixed in PR D), 2 policy pages, 3 others.
- **Orphans (no link from any page's main content):** `/products/portable-toilet-cabin` (#86 links it from the
  toilet-cabin category), `/marketplace`, `/faq`, `/careers`, `/privacy-policy` (all reachable from navigation
  or footer).

### 3.2 AEO — answer engine optimisation

- City, promotion and guide pages already use the question → direct answer pattern with visible FAQs that
  match their FAQPage markup.
- **Templated FAQs:** the promotion grid repeats the same five question templates per keyword; 22 questions
  appear on 9–10 pages each ("How long does delivery and installation take in Kerala?" …). City pages and
  guides have **no** templated questions.
- **Rich-result expectations:** since August 2023 Google shows FAQ rich results only for well-known
  government and health sites. Existing FAQPage markup is valid and is kept, but **no new FAQPage markup is
  added in this batch**, and nothing here promises FAQ rich results. QAPage is not used anywhere (correct).
- **F8 — products without an FAQ:** Executive Portable Cabin 20ft, Guard Security Cabin, Portable Cabin 40ft
  Bunkhouse, Luxury Prefab Villa G+1, Family Prefab Home 2BHK (1), Portable Toilet Block 4-Unit (1), Container
  Office (2), 20ft Storage Container. Seven are Merchant-fed, so any added Q&A must use only verified
  catalogue facts — see A7.
- Two blog posts word their FAQPage questions differently from the visible accordion (e.g. schema "Do I need
  BBMP approvals for portable cabins?" vs visible "Do I need BBMP approvals?") — A13.

### 3.3 GEO — generative engine optimisation (evidence and entity clarity)

- **Consistent entity facts:** one factory (Kamandoddi, near Hosur, Tamil Nadu 635117) and one Bangalore
  office (Electronic City, 560105), both from `src/lib/company.ts`; the Organization / LocalBusiness schema
  uses the factory address; the footer prints Udyam, GSTIN and ISO certificate numbers; `sameAs` lists three
  real profiles (Facebook, LinkedIn, Instagram). City pages state they describe delivery areas, not branches.
- **Requires verification:** the ISO 9001:2015 claim (hero chip, footer, `hasCertification`) — a withdrawal
  was prepared in commits that never reached `main`; the owner must confirm the certificate is current (A12).
- **F9 — no project evidence:** no completed-project, installation-photo or case-study module exists. This
  is the single largest GEO gap and **cannot be written by us** — it needs real projects, photos,
  permissions and dates (A8). A reusable module is proposed in section 6 for when evidence exists.
- **F11 — conflicting claims:** warranty tiers, lead times, materials, lifespans and company age disagree
  across pages. Issue #107 already lists every instance with suggested wording (W1–W8, P1–P8, M1–M6, D1–D15,
  Q1–Q12). **Nothing in this batch edits any of those claims.**

### 3.4 AIO — machine-readable layer

- JSON-LD parses on every page; Product/Offer appears only on product pages; ProductGroup on the size-ladder
  parent; categories with landing content use summary ItemLists without offers (correct — merchant listings
  are evaluated on product pages).
- **F3** — 16 city pages: BreadcrumbList last item uses `metaTitle`, the visible crumb uses `h1` (the
  inventory's substring check flags 14; on 2 more — e.g. Villa Construction — the meta title is only a prefix
  of the H1, which the full build diff caught)
  (fixed in PR D).
- `/products/home-construction/building-construction-contractor` and `/contact`: breadcrumb name differs
  slightly from the visible crumb (minor, not in this batch).
- `public/llms.txt` exists (Google does not use it; harmless). It says "delivered across India in 7-15 days"
  (dispatch alone is 7–15 working days, plus transit) and "40+ industrial hubs" (no source) — A11.

### 3.5 SXO — landing page to enquiry or purchase

- **Products:** all purchasable SKUs show price, GST statement, Add to Cart, dispatch window and transport
  rule above the fold. The rental page shows ₹14,000 (ex-GST base) beside ₹16,520 (incl. GST) — a correct
  breakdown, never fed.
- **Guides:** every guide ends in a "Ready to choose…" band (models + WhatsApp).
- **City pages (F7):** quotation box always links to `/contact`; call + WhatsApp buttons only on 6/27.
- **Forms:** the enquiry hardening (length limits, validation, rate limits, notification escaping) is in
  PR #86 with its own tests and a migration that must be applied after the code — not repeated here.
- **Mobile:** horizontal overflow was measured on 232 routes × 5 widths on 13 Oct 2026 (PRs #110, #114) — 0
  pages. Pages changed in this batch are re-measured at 320 px and 1440 px in their PRs.
- **Core Web Vitals:** not measurable here without field data; see section 9 for how to read them in GSC.
  No CWV claim is made.

## 6. Reusable architecture (what to build on, not duplicate)

| Need | Source of truth / component | Rule |
|---|---|---|
| Price, purchasability, feed | `src/data/productCommerce.ts` (`sellPrice`, `isPurchasable`, `isOutrightSale`, `feedEligible`), `src/data/merchantFeedPolicy.ts` | Every ₹ on any page is computed from these; never typed into copy. Protected. |
| Delivery and installation | `src/data/shippingZones.ts` (`DISPATCH_WORKING_DAYS`, `SHIPPING_ZONES`, `INSTALLATION`) | Lead-time copy must agree with these (see #107 D-series). |
| Company identity | `src/lib/company.ts` (`COMPANY`) | Addresses, phones, registrations — never hard-coded. |
| City pages | `src/data/cityPages.ts` → `app/(site)/cities-we-serve/[slug]/page.tsx` | One entry = one page; FAQPage from the rendered array; no ₹; disclaimers for named companies/landmarks. |
| Container-office cluster | `src/data/containerOfficeCluster.ts` + `ContainerOfficeLocations` | New container-office page ⇒ cluster entry (test-enforced). |
| Category landing sections | `src/data/categoryLandings.ts` + `CategoryLandingContent` (PR #86) | Computed comparison tables and FAQs; ₹ only via the catalogue (test-enforced). |
| Promotion hubs → city links | `CITY_LINKS_BY_PROMOTION` in `src/data/seoPromotions.ts` | One PR declares each hub key. |
| Breadcrumbs | `generateBreadcrumbSchema` + visible trail (PageHero `breadcrumbs`) | Schema names = visible crumbs. |
| Measurement | `npm run seo:inventory` and `npm run seo:gsc-report` (this PR; both use `scripts/seo/page-groups.ts`), `npm run seo:audit`, `npm run cities:audit`, `scripts/merchant-url-audit.mjs` | Re-run before and after every SEO PR. |

**Proposed, not built (needs owner evidence first):**

- *Project evidence module* — data entries `{ title, location (district-level), product, size, scope,
  completedOn, photos[], permission: true }` rendered on the matching product, category and city pages.
  Building it before any entry exists would ship an empty component, so it waits for the first verified
  project (A8).
- *Product FAQ data* — `{ productId, question, answer, source }` where `source` names the catalogue field or
  owner approval; rendered visibly on the product page with **no** new FAQPage markup on Merchant landing
  pages (A7).

## 10. How to re-run the inventory

```bash
npm run build
npx next start -p 3010            # in another terminal
npm run seo:inventory -- http://localhost:3010 --out ../seo-inventory-<date>
# or against production:
npm run seo:inventory -- https://portableofficecabin.com --out ../seo-inventory-prod-<date>
```

Outputs `inventory.csv` (the matrix in this file's column order), `inventory.md` (matrix + keyword map +
templated FAQs) and `inventory.json` (every raw measurement). It changes nothing and is not a CI gate.
